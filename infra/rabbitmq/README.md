# RabbitMQ — PLAT-05

`rabbitmq.conf` loads the topology generated by
[`scripts/gerar_segredos.py`](../../scripts/gerar_segredos.py). The generated
file is `secrets/definitions.json`; the Compose service must mount it at
`/etc/rabbitmq/definitions.json` and mount this directory as the RabbitMQ
configuration directory.

The definition contains durable topic/direct/fanout exchanges, durable queues,
bindings, service users, queue-level permissions and dead-letter routing. The
API user carries the `monitoring` tag for the Management HTTP API. Its proposed
read permission on `q.dlq` is required for the non-destructive DLQ sample in
PLAT-07 and still needs review in the shared architecture contract.

These files do not activate RabbitMQ in the current Compose stack. That Compose
file is shared and remains unchanged pending explicit authorization.
